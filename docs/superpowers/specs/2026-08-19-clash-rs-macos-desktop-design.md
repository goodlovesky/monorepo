# Clash RS macOS 桌面版设计

## 1. 目标

在现有多端代理项目中新增完整的 macOS 桌面体验。界面以 `docs/mac-1001.png` 为视觉基准，保留 Clash RS 品牌，并将截图中的首页、导航、订阅、节点、网络模式和流量信息连接到真实业务状态。

本次交付同时实现 macOS 系统代理和需要管理员验证的虚拟网卡全局接管，并输出 Apple Silicon 与 Intel 通用的可下载安装包。

## 2. 范围

### 2.1 包含

- macOS 独立桌面壳、窗口和菜单栏交互。
- 首页、代理、订阅、连接、规则、日志、测试和设置八个页面。
- 订阅导入、更新、切换、编辑、删除、流量与到期信息。
- 代理组、节点选择、延迟测试和当前节点状态。
- 规则、全局、直连三种模式的实时切换。
- 活动连接、规则、实时日志、网络测试和流量统计。
- macOS 系统代理模式。
- 管理员助手提供的虚拟网卡模式。
- 异常退出后的系统代理、路由和 DNS 恢复。
- macOS 12+ 通用 `.app` 和 `.dmg` 打包。

### 2.2 不包含

- 替换 Android 现有界面或 VPN 实现。
- 重写已有配置仓库、导入器和代理控制器。
- 依赖 Apple Network Extension 特殊权限的发布方案。
- 本阶段的 Windows 和 iOS 界面实现。

## 3. 多端边界

```text
app/lib/
├── core/                   # 共享核心、控制接口和运行配置
├── models/                 # 共享配置、节点、连接、规则和流量模型
├── services/               # 共享订阅、设置、日志和业务编排
├── features/
│   ├── mobile/             # Android 现有页面
│   └── desktop/            # macOS 桌面壳与八个页面
└── platform/
    ├── android/            # Android VPN 接管
    └── macos/              # 系统代理、助手、窗口与托盘

crates/
├── core-bridge/            # 多端共享代理核心
└── macos-helper/           # macOS 管理员级虚拟网卡助手
```

`main.dart` 仅负责平台分流和全局主题。Android 进入现有竖屏应用，macOS 进入桌面壳。页面不直接操作平台命令，而是通过统一服务接口控制核心和系统网络。

## 4. 桌面视觉与布局

### 4.1 窗口

- 默认内容尺寸约 `1440×1050`。
- 最小内容尺寸 `1180×760`。
- 使用 macOS 系统标题栏和红黄绿窗口按钮。
- 窗口标题、应用名称和安装包名称统一为 `Clash RS`。
- 关闭主窗口时默认驻留菜单栏，显式退出时执行网络清理。

### 4.2 主布局

- 左侧为 `304 px` 宽的固定导航栏，包含品牌、八个导航项、实时速率折线和总流量。
- 右侧顶部为页面标题和快捷操作栏。
- 内容区使用参考图的暗色背景、蓝色强调色、圆角卡片、双列栅格和细边框。
- 宽窗口为双列，低于 `1240 px` 时内容区改为单列，导航栏保持固定。
- 所有实时数据使用单一控制器状态源，界面不使用截图中的固定示例值。

## 5. 页面定义

### 5.1 首页

- 订阅卡：名称、来源、更新时间、已用/总量、剩余百分比和更新操作。
- 当前节点卡：当前分组、节点、类型、特性标签和延迟。
- 网络设置卡：系统代理与虚拟网卡二选一，显示真实运行状态和开关。
- 代理模式卡：规则、全局、直连三模式。
- 流量统计卡：上行、下行、活动连接数和近期折线。

### 5.2 代理

- 顶部代理组标签和全组测速。
- 节点使用自适应双列卡片，显示名称、协议、延迟和选中状态。
- 点击节点立即更新当前代理组，失败时恢复原选中项。

### 5.3 订阅

- 支持 URL、本地文件和粘贴内容导入。
- 支持更新、编辑、切换、删除、手动刷新和自动更新间隔。
- 从订阅响应头和配置元数据中解析流量、到期时间和最后更新时间。

### 5.4 连接

- 展示活动连接的来源、目标、网络类型、命中规则、上下行流量和开始时间。
- 支持搜索、排序、关闭单条和关闭全部连接。

### 5.5 规则

- 展示规则类型、匹配内容和策略。
- 支持关键字搜索和规则类型筛选。

### 5.6 日志

- 展示实时日志时间、级别和内容。
- 支持级别筛选、关键字搜索、暂停滚动、清空和导出。

### 5.7 测试

- 执行直连网络、代理连通、DNS 解析、节点延迟和出口地址检查。
- 每个测试都显示独立进度、耗时、结果和可重试状态。

### 5.8 设置

- 应用：开机启动、关闭驻留、托盘和界面密度。
- 网络：监听地址、HTTP/SOCKS/混合端口、系统代理、虚拟网卡、DNS 和绕过地址。
- 行为：启动时恢复上次模式、订阅自动更新和异常自动重启。

## 6. 系统代理

`MacSystemProxyService` 管理系统代理生命周期：

1. 枚举已启用的 macOS 网络服务。
2. 启用前记录每个服务的 HTTP、HTTPS、SOCKS 和绕过列表。
3. 启动普通权限的共享代理核心。
4. 通过 macOS 网络配置命令将代理指向 `127.0.0.1` 的应用端口。
5. 停止、切换到虚拟网卡、显式退出或崩溃恢复时，回写原始网络设置。

恢复状态持久化到应用支持目录的独立恢复文件。应用启动时如发现上次未完成清理，先恢复再启动新模式。

## 7. 虚拟网卡与管理员助手

### 7.1 安装

- `macos-helper` 构建为通用 Mach-O 可执行文件，并随 `.app` 打包。
- 首次启用虚拟网卡时，应用使用 macOS 管理员验证安装或更新助手。
- 助手的版本与应用内置版本不同时执行可验证替换。

### 7.2 通信

- 应用与助手使用本地 Unix Domain Socket 通信。
- 协议为按行分隔的 JSON，命令包括 `status`、`start`、`stop`、`restore` 和 `version`。
- 每条命令包含随机会话令牌；助手只接受当前用户的应用请求和应用支持目录中的运行配置。

### 7.3 运行

1. 应用生成包含 TUN、自动路由、DNS 劫持和当前代理模式的运行配置。
2. 助手以管理员权限启动独立代理核心进程并配置虚拟网卡、路由和 DNS。
3. 界面继续通过本地控制器读取节点、延迟、连接和流量。
4. 停止时助手先停止核心，再恢复 DNS 和路由，最后移除虚拟网卡状态文件。

### 7.4 互斥

系统代理和虚拟网卡是互斥运行模式。切换时必须完整停止旧模式和恢复其系统状态，再启动新模式。任何一步失败都执行 `restore` 并将界面开关恢复为关闭。

## 8. 菜单栏和窗口生命周期

- 菜单栏图标显示当前运行状态。
- 菜单项包括显示主窗口、启动/停止、系统代理、虚拟网卡、规则/全局/直连、当前节点和退出。
- 关闭主窗口仅隐藏窗口；菜单栏退出执行网络恢复。
- 启动时检查普通核心、助手核心和恢复文件，将观测到的真实状态同步到界面。

## 9. 数据流

```text
桌面页面
  → DesktopAppController
    → 共享 ProfileRepository / SettingsRepository
    → ClashController (proxies, traffic, connections, rules, mode)
    → MacNetworkModeService
         ├── MacSystemProxyService → macOS 网络服务
         └── MacTunService → macos-helper → TUN / route / DNS
```

UI 只消费不可变快照。所有切换操作先进入忙碌状态，服务层完成核心和系统状态验证后才发布新快照。

## 10. 错误处理

- 订阅错误保留原配置和原激活项。
- 节点切换失败恢复原节点。
- 系统代理修改部分失败时，回滚所有已处理网络服务。
- 助手安装、通信、TUN 创建、路由或 DNS 任一失败时，执行完整恢复并记录可操作的错误说明。
- 应用启动时检测残留网络状态并自动清理。
- 所有平台命令都有超时、结构化结果和日志记录。

## 11. 测试与验收

### 11.1 自动测试

- 共享模型、配置、订阅和设置回归测试。
- 桌面路由、导航、宽屏/窄屏布局和关键卡片组件测试。
- 系统代理命令解析、原状态快照、应用和回滚测试。
- 助手 JSON 协议、令牌、超时、幂等启停和恢复测试。
- Rust 核心和 macOS 助手测试。

### 11.2 实机测试

- 导入真实订阅，更新、激活并选择节点。
- 系统代理开启后验证 HTTP、HTTPS、SOCKS 和浏览器出口。
- 虚拟网卡开启后验证全局路由、DNS、UDP 和应用流量。
- 系统代理与虚拟网卡反复切换，验证无残留代理、路由和 DNS。
- 强制结束应用或助手后重新启动，验证恢复逻辑。
- 节点切换、测速、模式切换、连接关闭和日志导出。

### 11.3 视觉验收

- 默认窗口截图与 `docs/mac-1001.png` 对照。
- 检查窗口比例、导航栏宽度、卡片栅格、色彩、间距、圆角、字号、高亮状态和滚动区域。
- 以实际数据填充后检查超长订阅、节点和规则文本的截断与提示。

## 12. 打包与交付

- 分别构建 `arm64` 和 `x86_64` 的 Flutter 桌面程序、代理核心和管理员助手。
- 使用 `lipo` 生成通用二进制，验证架构和动态库引用。
- 将 `.app` 、助手、图标、字体、许可说明和恢复脚本打包为 `.dmg`。
- 默认生成 ad-hoc 签名的可下载构建；构建环境中存在 Developer ID 时，同一脚本执行完整签名和公证。
- 输出 `.app`、`.dmg`、SHA-256、构建日志、安装说明、验证记录和可执行回滚脚本。

## 13. 完成条件

1. Android 现有分析、测试、构建和 VPN 路径保持通过。
2. macOS 八个页面可从左侧导航进入，关键卡片连接真实数据。
3. 系统代理和虚拟网卡都完成实机网络验证。
4. 系统代理、路由、DNS 和助手状态在停止、切换、退出和异常后正确恢复。
5. 默认窗口截图通过与参考图的视觉对照。
6. 通用 `.dmg` 可在 macOS 12+ 的 Apple Silicon 和 Intel 设备上安装。
