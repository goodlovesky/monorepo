# Clash RS 桌面端 1:1 UI 与 VPN 功能设计

## 目标

使用 Flutter 为 macOS 与 Windows 提供同一套桌面界面，在固定 `960×720` 逻辑像素窗口中，逐页复刻本地参考截图。参考截图不纳入版本库。保留 Clash RS 名称和现有图标，其余布局、颜色、字体、间距、控件、状态及信息密度以参考截图为准。

桌面 VPN 与代理功能可重新设计，但必须提供可验证的核心启停、订阅、节点、代理模式、系统代理、TUN、连接、规则、日志和测速闭环。

## 平台与窗口合同

- macOS 与 Windows 共用 Flutter 页面、组件、主题、状态模型和业务控制层。
- 平台差异仅存在于窗口控制、系统代理、TUN、权限提升、托盘和安装包实现中。
- 窗口固定为 `960×720` 逻辑像素。
- 禁止最大化、全屏及拖拽缩放。
- 页面内容必须在固定窗口内保持参考截图的结构；长列表仅在其内容区域滚动。

## UI 架构

建立统一的桌面设计系统，集中定义：

- 背景、面板、边框、强调色、文本色和状态色；
- 字号、字重、行高和字体回退；
- 侧栏、标题栏、卡片、表格、按钮、输入框、开关和标签尺寸；
- 页面边距、栅格间距、圆角、分隔线及选中状态；
- 空数据、加载、错误、禁用和悬停状态。

桌面视觉层拆分为可复用组件：桌面外壳、导航项、页面标题栏、面板、数据表格、代理节点卡、设置行、状态图表、筛选栏和操作栏。现有代理控制器、配置导入、运行状态和存储逻辑可以复用，但不得让既有组件样式限制截图复刻。

## 页面映射

### 统一外壳

复刻原生标题栏下方的深色应用区域、固定左侧导航、底部实时流量图、页面标题和顶部操作按钮。导航选中态、图标尺寸、文字基线及分隔关系在全部页面保持一致。

### 首页

覆盖订阅信息、当前节点、网络设置、代理模式、流量统计、网站测速、IP 信息、Clash 核心信息和系统信息。卡片采用参考图中的双栏栅格、标题图标、数据排布和状态颜色。

### 代理

覆盖代理组筛选、视图工具栏、双列节点卡、节点协议标签、延迟状态、当前节点高亮及节点切换。

### 订阅

覆盖订阅卡片、刷新、导入、编辑、删除、自动更新和扩展配置区域。

### 连接

覆盖连接统计、筛选、搜索、实时连接表格和关闭单条或全部连接。

### 规则

覆盖规则搜索、编号、匹配内容、规则类型和目标策略列表。

### 日志

覆盖日志等级筛选、搜索、暂停、清空和实时日志列表。

### 测试

覆盖三列服务检测卡、单项检测、状态展示和全部检测。

### 设置

覆盖两张设置参考图中的分组、开关、下拉框、端口输入、二级入口和高级设置。所有设置必须写入统一状态模型，并与运行中的核心配置保持一致。

## VPN 与代理数据流

Flutter 控制层负责：

1. 读取本地设置、订阅和上次运行状态；
2. 生成或选择 Mihomo 配置；
3. 启动核心并执行健康检查；
4. 通过 Mihomo API 获取代理组、节点、连接、规则、日志和流量；
5. 将用户操作写回核心及持久化状态；
6. 在系统代理或 TUN 状态变化后读取系统真实状态并更新界面。

代理模式支持规则、全局和直连。网络接管支持系统代理和 TUN。Mac 使用签名 Helper 执行需要提升权限的网络操作；Windows 使用后台服务及系统代理接口。程序退出、核心崩溃或模式切换失败时，控制层恢复受管理的系统代理设置，并在界面中展示实际结果。

## 错误与状态设计

- 核心启动失败：保留错误摘要和日志入口，界面不得显示为已连接。
- 订阅导入或刷新失败：保留原有效配置，显示失败原因和重试入口。
- 系统代理或 TUN 设置失败：回读系统状态，恢复开关，并显示平台返回结果。
- Mihomo API 暂时断开：进入重连状态，不清空最后一次有效数据；恢复后重新同步。
- 页面空数据：使用与参考视觉一致的空状态，不使用异常尺寸的默认 Flutter 占位组件。

## 视觉验收

以 12 张参考图为基准，在 `960×720` 窗口中为每个页面生成实际截图。逐项校准：

- 窗口与侧栏比例；
- 页面标题和工具按钮位置；
- 卡片、表格和列表边界；
- 字体基线、字号、字重和行高；
- 背景、边框、强调色和状态色；
- 控件高度、内边距、栅格间距和信息密度。

验收时不得以“风格相似”代替逐页对比。品牌名称和图标是唯一明确允许与参考截图不同的视觉内容。

## 功能与构建验收

- 验证核心启动、停止及异常恢复。
- 验证 URL 订阅导入、刷新、编辑、删除和自动更新。
- 验证节点选择、延迟检测和代理组同步。
- 验证规则、全局、直连三种代理模式。
- 验证系统代理和 TUN 的启用、停用、状态回读及退出恢复。
- 验证连接、规则、日志、流量和服务检测的实时数据。
- 运行 Flutter 静态检查、单元测试和组件测试。
- 运行 Rust 核心测试。
- 构建并启动 macOS `.app`，生成和验证 `.dmg`。
- 验证 Windows Flutter 构建配置和安装包合同。

## 交付与恢复

修改前保留原始副本与哈希；交付修改后的源码、差异文件、验证记录和可执行回滚脚本。最终 macOS 成品必须从当前源码重新构建，并在固定窗口中完成启动和逐页验证。
