# Clash RS 桌面端六语言本地化设计

## 目标

将 Clash RS 桌面端从“语言设置只影响少量导航文字”升级为完整的离线本地化系统。用户切换语言后，全部桌面页面、弹窗、操作提示、空状态和面向用户的错误信息立即刷新，无需重新启动应用。

## 支持语言

| 设置值 | Flutter Locale | 显示名称 |
| --- | --- | --- |
| `zh-CN` | `zh_CN` | 简体中文 |
| `zh-TW` | `zh_TW` | 繁體中文 |
| `en-US` | `en_US` | English |
| `ja-JP` | `ja_JP` | 日本語 |
| `ko-KR` | `ko_KR` | 한국어 |
| `fr-FR` | `fr_FR` | Français |

简体中文是模板语言和最终回退语言。

## 技术方案

采用 Flutter 官方 ARB 与 `gen_l10n`：

- 在 `app/lib/l10n/` 保存六份 ARB 文件。
- 使用 `app_zh.arb` 作为模板。
- 由 Flutter 在构建时生成强类型 `AppLocalizations` 接口。
- 在 `MaterialApp` 注册生成的 delegates 和 supported locales。
- 现有 `ThemeController` 继续负责保存语言代码和通知应用刷新，不再承担字符串翻译职责。
- 增加轻量的 `BuildContext` 扩展，让页面统一通过 `context.l10n` 访问翻译。

所有翻译内容随应用打包，不连接在线翻译服务，不在运行时下载语言文件。

## 本地化覆盖范围

### 桌面框架

- 应用标题之外的侧边栏导航。
- 页面标题、顶部操作、托盘菜单和通知层。
- 网络切换状态、错误横幅和退出流程。

### 页面

- 首页及全部统计卡片。
- 代理组、节点标签、测速状态和代理异常。
- 订阅的输入、导入、创建、刷新、扩展配置和空状态。
- 活动连接、筛选、排序、关闭连接和空状态。
- 规则、日志、测试及其工具栏和结果。
- 基础设置、高级设置、所有设置弹窗及操作结果。

### 共用提示

- `ProxyAppController`、网络服务和导入服务产生的用户可见状态，改为稳定的消息键或结构化错误，由界面层翻译。
- Mihomo 原始日志、服务器返回文本、订阅名称、代理组名称、节点名称、域名、IP、路径和版本号保持原文。
- 技术诊断导出默认保留稳定字段名，另附当前界面语言；诊断内容不要求逐条翻译底层原始日志。

## ARB 结构

翻译键按功能分组命名：

- `nav*`：主导航。
- `common*`：通用按钮和状态。
- `home*`：首页。
- `proxy*`：代理页面。
- `subscription*`：订阅页面。
- `connections*`：连接页面。
- `rules*`、`logs*`、`test*`：对应页面。
- `settings*`：设置页面与弹窗。
- `error*`：面向用户的错误信息。
- `notification*`：通知与提示条。

包含变量的文本使用 ARB placeholder，例如版本号、延迟、文件路径、流量值、数量和剩余时间。不得通过字符串拼接改变语序。

## 语言切换数据流

1. 用户在设置页面选择语言。
2. `AppSettings.language` 保存新代码。
3. `ProxyAppController.updateSettings` 调用 `ThemeController.setLanguage`。
4. `ThemeController` 通知根 `MaterialApp` 重建。
5. 根组件把语言代码映射成 Locale。
6. Flutter 加载对应的生成本地化对象。
7. 所有订阅 `context.l10n` 的桌面组件立即显示新语言。

应用重启时，设置仓库和偏好文件继续恢复最后一次选择。未知或已废弃语言代码统一回退到 `zh-CN`。

## 布局适配

- 桌面窗口继续固定为 `960 × 720`。
- 英语、法语等较长文本优先使用 `Expanded`、省略号、可换行提示和稳定的最小间距。
- 按钮不得因法语文本产生溢出。
- 日语、韩语和繁体中文使用现有系统字体回退；现有图标和卡片尺寸保持不变。
- 数字、端口、IP、版本、流量单位和节点延迟保持统一格式。

## 翻译原则

- 产品名称始终为 `Clash RS`，不得出现 `Verge`。
- `Mihomo`、`TUN`、`System Proxy` 等技术名称按各语言常用表达处理，同时保留必要英文术语。
- 繁体中文使用台湾常用界面词汇。
- 日语、韩语和法语使用简洁的软件界面语气。
- 不翻译用户配置、节点名称或服务端内容。

## 错误处理

- 本地化资源缺失时由模板语言回退，不显示空白。
- 未识别语言代码回退到简体中文并保存规范化代码。
- 需要展示底层错误时，先显示翻译后的错误类别，再附上原始技术详情。
- 语言切换失败不得改变代理运行状态或网络模式。

## 测试与验收

### 自动测试

1. 六种 Locale 都能生成并加载。
2. 六份 ARB 拥有相同的消息键和 placeholder 定义。
3. 设置语言后 `MaterialApp` 立即使用对应 Locale。
4. 语言设置持久化并在重启后恢复。
5. 桌面导航和每个页面至少验证一个代表性翻译。
6. 产品相关资源和用户可见字符串不得包含 `Verge`。
7. 新增静态检查扫描桌面页面中的未迁移中文界面字面量，并为允许保留的诊断或原始文本建立明确白名单。
8. `flutter analyze` 和完整 `flutter test` 通过。

### 手动验收

在 macOS Release 构建中依次切换六种语言，检查：

- 当前页面即时刷新。
- 八个侧边栏页面全部切换。
- 设置页两列、弹窗、下拉选项和提示完整翻译。
- 法语长文本没有溢出。
- 切换语言不会关闭系统代理、TUN 或代理核心。
- 重启后仍保持最后选择的语言。

## 交付范围

- 全部桌面页面和共用用户提示迁移。
- 六语言测试和硬编码检查。
- 更新 README 中的语言支持说明。
- 重新构建并启动 macOS Release 供测试。

## 非目标

- 本轮不翻译 Android 专属页面。
- 本轮不翻译 Mihomo 原始日志或订阅提供者返回内容。
- 本轮不增加在线语言包、机器翻译接口或远程配置。
- 本轮不改变代理协议、网络模式实现、UI 视觉设计或固定窗口尺寸。
